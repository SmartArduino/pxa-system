# C++ SDK 第二轮接口与性能审计（2026-10-09）

参考版本是 `b3426c0`，先前的基础类型、Surface 和标量 Storage 封装已分组提交。
本轮继续处理普通服务的参数生命周期和任务嵌套，并补齐可选事件类型匹配。
没有更改 Host ABI、默认容量或 voxel 的画质/绘制配置。

| 原因 | 修改与收益 | 内存变化 | 验证 |
| --- | --- | --- | --- |
| 字节 Storage 延迟读取 key/value；保存 4 B 也嵌套两项服务任务 | get/set/remove/list 创建任务时编码；拥有式封包只复制有效载荷。外部封包单独处理键和值的重叠；list 校验严格分页并在错误时保留旧输出 | 默认 set 封包上限仍 512 B，类型化标量仍按容量使用；不添加服务字段或池。应用加服务的峰值 3→2 槽 | 临时字符串/值销毁、最大键和 2048 B 值、默认封包精确边界、别名、取消、晚到响应及提交失败 |
| Permission 默认接口也延迟读取 name/scope 并嵌套任务 | check/acquire 创建时编码，只有一项服务任务；无效输入不分配槽。损坏的成功结果有可识别句柄时回收，取消后的晚到授权仍关闭 | 默认封包上限仍 512 B；只复制载荷；无新服务字段/池；峰值 3→2 槽 | 默认和外部封包、最大名称/1024 B scope、重叠输入、损坏布尔值和句柄、拒绝/取消/停止阶段 |
| 应用通过 service/opcode 数字分流通知 | 可选 `events.hpp` 提供 `event.is<T>()`，迁移 device-sensor、IPC provider、Work job | Event 布局不变；无订阅表、缓存或任务；头文件只前置声明各服务类型 | 七类真实有效消息均通过匹配与对应解码；错误类型不匹配，损坏的匹配消息保留给解码器报错 |

所有异步操作仍须让 Context 活到完成/取消；输出与外部 packet 是借用。
外部 packet 不得给多个未完成请求复用。事件类型匹配不验证 token/载荷，
也不代替 IPC 契约/endpoint、Canvas 页面代次或资源句柄匹配。
默认拥有式封包容量未缩减，未使用的能力不引入全局缓存或默认字段。

## 可复现对照与边界

原生模拟基准使用同一个源文件、编译器和 `-O3`，固定 CPU，交替前后顺序，
每个请求类别 12 轮，每轮 200 万次。测量包括 SDK 编码、任务调度、模拟提交和
完成回调，排除了真实 Host、IO、队列、显示、设备与游戏循环。

| 指标 | 参考版 | 本轮 |
| --- | ---: | ---: |
| Storage set 中位耗时（原生模拟，ns/请求） | 93.37 | 94.35 |
| Permission check 中位耗时（原生模拟，ns/请求） | 119.07 | 106.42 |
| 参考请求的真实任务槽峰值（每轮独立进程） | 3 | 2 |
| 默认池预留（B） | 8208 | 8208 |
| 两槽配置池预留（B） | 原默认请求无法同时容纳应用及两项服务任务 | 2064，Storage/Permission 回归均通过 |
| 同一 Storage/Permission 探针 Wasm 文件（B） | 52111 | 52256 |
| 探针初始线性内存（B） | 131072 | 131072 |
| 探针线性内存上限（B） | 2097152 | 2097152 |

Storage 耗时基本持平（约 +1%，测量波动范围重叠），不宣称提速。
Permission 原生模拟中位值约下降 11%；这不是设备实测结论或游戏 FPS 收益。
任务槽峰值是在本轮独立进程中测量，完成/取消后归零，未拿历史累计峰值充当
本轮峰值。两槽配置是应用可选参数，不改变默认八槽。

创建任务时拥有参数会使用短暂的调用栈空间；`-fstack-usage` 检查中创建默认
拥有封包的入口分别使用 1096 B（Storage set）和 1112 B（Permission）静态栈，
包括构造封包和传入协程时的暂存；旧入口把编码延后到协程中。这是原生
Clang 的单函数静态栈结果，不是设备/Wasm 全调用链栈峰值。
这部分成本没有通过增大默认栈、线性内存或池来解决，但不能宣称活跃栈字节
峰值完全不变。原生可写符号的字段/大小没有增加；ELF BSS 总大小受链接对齐
影响，不作为设备 SRAM 结论。探针 Wasm 文件增加 145 B，
也不能由线性内存不变推导代码映射、PSRAM 或设备真实堆峰值不变。
本轮没有安装真机包或测显示帧率。

验证记录：完整 Guest C++ 回归；六项定向 ASan/UBSan（检测返回后栈使用）；
Storage/Permission 读取全部提交字节的 MSan 检查；两槽配置的两个生命周期
回归。storage、device-sensor、ipc-stats、work 生成 Wasm 和三种 AOT。
日志和完整样本在工作区 `local/sdk-followup-20261009/`。

## 下一步优先项

1. **减少拥有式入口的创建时暂存**。默认字节封包仍为 512 B，创建参数快照
   目前有两份短暂栈存储。后续应研究直接在最终协程帧内初始化的有界构造，
   保留创建时拥有参数、无 Host 提前调用及失败/取消语义；不能以再加全局
   scratch 或扩大默认栈掩盖成本。
2. **明确自定义数据 codec**。标量 Storage 已有，但结构存档仍要自行选择字段、
   版本和校验和。可选 schema/codec 应声明最大编码容量、按值编码及严格解码，
   不写入原生 struct，不给所有应用默认配置大型包。
3. **有进度的部分读写**。File、NetBody、PCM 的短传输和 would_block 仍由调用者
   处理。可增加显式状态的 transfer helper，持有 offset/已完成量，在事件中
   继续；不忙等，不隐式复制数据或伪装成已完成的 read<T>()。
4. **Surface 放弃租约**。未 present 的 SurfaceFrame 析构会关闭整个 Surface。
   当前协议缺少独立的安全归还动作；discard/release 需要 Host/Guest 一起设计，
   不能只在 SDK 标记 buffer 空闲，也不能无证据复用正在扫描的帧缓冲。
5. **事件订阅与匹配覆盖**。七类匹配已完成；窗口/UI 环境通知与带任务作用域的
   有界订阅仍有空间。新增订阅应默认零容量，不让所有 Context 持有最大表，
   并验证取消、重复注册、撤销、页面代次和晚到通知。
6. **容量与真实性能统计**。现在只有池预留/槽计数等统计，未直接提供每项服务
   协程帧字节和本次运行的活跃栈峰值。可以做可选诊断，先验证统计自身的成本。
   阶段计时应继续区分 Guest、编码/提交、Host、队列与实际显示，不能把一次
   co_await 的等待时间当作 CPU 时间。

这些是后续设计项；本轮未改变文件流协议、Surface ABI 或设备显示流水线。
