# C++ 国际化 SDK

这是按需使用的 C++ SDK 模块，不依赖 Guest C SDK。翻译在构建时编译为只读目录；
运行时支持类型化消息、具名参数、复数、序数、分支选择、数字格式和系统语言更新。
不创建全局翻译器，不预留翻译缓存，也不在设备上解析 YAML。

## 最小用法

```cpp
#include <pxa/i18n.hpp>
#include <pxa/events.hpp>
#include "pxa_app_messages.hpp"

namespace messages = pxa::messages::app_pxa_cpp_i18n;
pxa::i18n::Translator strings{messages::bundle};

auto title = strings.text(messages::title); // string_view，借用只读目录
auto label = strings.format(messages::args::items{.count = 3});
if (label) {
    // *label 是拥有内容的 std::string，可移动到 State<std::string>。
}
```

`format()` 先验证参数并测量所需 UTF-8 字节数，再生成字符串。短文本可由标准库的
短字符串优化处理；长文本只创建一个结果字符串，不创建参数容器或翻译缓存。
不同语言的文字长度无需相同。返回值拥有内容，不受后续语言切换影响。

接收用户输入等长度不受控的参数时，可使用
`strings.format_limited(4096, messages::args::welcome{.name = name})`。
这个限制是最终输出的 UTF-8 字节数，不含末尾 NUL；超限在分配前返回 `limit_exceeded`。
`strings.formatted_size(...)` 只测量、验证，不分配。

动态分配遵循 `std::string` 的分配器和失败规则。默认 Guest 关闭异常，内存耗尽时
不能靠 `Result` 捕获标准库的分配失败。内存预算严格的地方可以使用下面的固定缓冲区接口。
所有格式错误、缺失消息、非法参数和显式长度限制都通过 `Result` 返回。

## 游戏 HUD 和固定缓冲区

```cpp
std::array<char, 128> buffer;
auto text = strings.format_to(buffer, messages::args::items{.count = 3});
if (text) {
    // *text 借用 buffer；成功时写入末尾 NUL。
}

pxa::i18n::TextBuffer<127> owned;
auto result = owned.format(strings, messages::args::items{.count = 3});
```

`format_to` 和 `TextBuffer` 不分配，容量不足返回错误，既不截断 UTF-8，也不覆盖旧内容。
容量按字节计算。输入字符串与输出缓冲区重叠会返回 `invalid_argument`；目录和数字符号
也不能借用输出缓冲区。输入必须是有效 UTF-8，不允许内嵌 NUL。

具名参数记录由生成器创建，是普通聚合类型，可以使用 C++ 指定初始化器。
也可以用位置参数：`strings.format(messages::items, std::uint32_t{3})`。
位置顺序是参数名的字母序，生成头文件会注明。具名写法更适合多个参数。

参数类型为 `string`、`u32`、`i32`、`u64`、`i64`、`number`。有符号和无符号不能混用，
宽整数不能传入窄类型，`bool` 不能作为数字。`string` 接受 `string_view`、`std::string`
和有边界的字符数组；裸指针请先构造成长度明确的 `string_view`。
`number` 使用 `Decimal{coefficient, scale}`，表示 `coefficient / 10^scale`，scale 范围 0..18。
例如 `Decimal{120, 2}` 为 `1.20`，复数规则保留其可见小数位数，和整数 `1` 不混同。

## 翻译文件与构建

在应用目录放置 `i18n/messages.yaml`：

```yaml
namespace: app.inventory
default_locale: en
messages:
  title:
    source: "Inventory"
    context: "Page title"
  items:
    source: "{count, plural, =0 {Empty} one {# item} other {# items}}"
    context: "Inventory count"
    placeholders:
      count: u32
```

`i18n/zh-CN.yaml`：

```yaml
locale: zh-CN
translations:
  title: "背包"
  items: "{count} 件物品"
```

`pxa_add_app` / `pxa_add_component(... CPP ...)` 自动编译该目录中的翻译，生成
`pxa_app_messages.hpp` 并加入目标的 include 路径。上述 namespace 生成
`pxa::messages::app_inventory`；源目录不需要保存生成头文件。
没有 `i18n/messages.yaml` 的应用不会新增生成步骤或国际化状态。

模块或自定义路径可以显式配置：

```cmake
pxa_add_module(inventory CPP SOURCES inventory.cpp)
pxa_add_translations(inventory
    SOURCE translations/messages.yaml
    LOCALES translations/zh-CN.yaml translations/ru.yaml
    OUTPUT inventory_messages.hpp
    NAMESPACE my_app::inventory_messages)
```

`NO_TRANSLATIONS` 关闭 component 的自动配置。默认生成语言随 component 的 C/C++ 类型选择；
显式 `LANGUAGE cpp` / `LANGUAGE c` 也可指定。C 生成器仅保留原有简单占位符能力。
翻译文件和 CLDR 数据均为构建依赖；生成内容不变时不会重写头文件，避免无效重编译。
独立导出的 C++ SDK 包含相同生成器和所需 CLDR 数据。

手动生成可使用：

```sh
python3 tools/i18n/compile_catalog.py app/i18n/messages.yaml \
    app/i18n/zh-CN.yaml app/i18n/ru.yaml \
    --language cpp --output generated/pxa_app_messages.hpp
```

YAML 输入支持缩进的映射和单行标量，是标准库实现的受限格式；不支持列表、锚点、
多行块或任意 YAML 类型。重复键、未知字段、标识符碰撞、参数不匹配及非法模板在构建时拒绝。
翻译允许缺少消息，查找时按消息回退。`max_bytes` 检查的是翻译源模板字节数；运行时生成长度
请使用 `format_limited` 或有界缓冲区限制。

## 模板能力

支持 `{name}`、`{amount, number}`、`plural`、`selectordinal`、`select`，可嵌套：

```text
{gender, select,
  female {She has {count, plural, one {# apple} other {# apples}}}
  other {They have {count, plural, one {# apple} other {# apples}}}}
```

每个选择必须有 `other`，分支不能重复。`=0` 等精确数值优先于复数类别。
`#` 表示最近一层 plural/selectordinal 的数值，嵌套 select 不改变该数值。
最多 32 个参数、8 层嵌套，每组最多 255 个分支，每条编译后程序最多 65535 字节。
单引号在 `{`、`}`、`#` 前开始引用，`''` 为一个单引号；`don't` 可直接书写。
不支持 plural offset、日期、时间、货币、单位和任意 ICU 格式样式。

复数和序数规则来自固定的 Unicode CLDR 48；生成器只嵌入应用实际使用的语言及规则。
运行时采用整数精确运算，支持可见小数尾零、负数与 64 位边界，不依赖浮点转换。
规则中的紧凑数字指数 c/e 为 0；不支持紧凑记数法。

数字符号是目录的可选配置：

```yaml
number_symbols:
  decimal: ","
  group: " "
  digits: "0123456789"
  primary_group: 3
```

`secondary_group: 2` 可以表达印度式 `12,34,56,789`。`digits` 必须包含十个不同 Unicode
码点。没有配置时使用 ASCII 数字、点号、不分组；不自动加载全量 CLDR 数字格式。
`{n}` 使用基础数字形式，`{n, number}` 与 `#` 使用该消息实际来源目录的数字符号。
独立数字格式可以调用 `format_number_to(buffer, Decimal{123456, 2}, &symbols)`。

## 系统语言与回退

```cpp
pxa::Result<void> on_start(pxa::Context&, std::span<const std::byte> config) {
    auto changed = strings.initialize(config);
    if (!changed) return std::unexpected(changed.error());
    return refresh_labels();
}

pxa::Result<bool> on_event(pxa::Context&, const pxa::Event& event) {
    if (!event.is<pxa::SystemEnvironment>()) return false;
    auto changed = strings.update(event);
    if (!changed) return std::unexpected(changed.error());
    if (*changed) {
        auto refreshed = refresh_labels();
        if (!refreshed) return std::unexpected(refreshed.error());
    }
    return true;
}
```

没有 START 语言记录时保留目录默认语言；配置损坏返回错误。重复语言/方向更新返回 false。
`Translator` 自己保存最长 63 字节的语言标签，事件销毁后仍有效。
底层 `decode_system_environment` 返回的 `SystemEnvironment::locale` 借用事件或 START 数据，
只适合在回调内使用。桌面 Host 同样转发语言更新，并在 START 中携带方向。

`set_locale("zh-TW")` 是应用的本地覆盖，不修改设备设置；后续系统事件可以覆盖它。
语言标签按现代 BCP 47 结构校验并规范大小写；不含完整 IANA 注册表别名、祖父标签转换和独立的 `x-...` 私有标签。
目录使用规范化的基础语言标签，运行时请求还可以携带扩展和 private-use。

回退按单条消息查找：完整标签 → RFC 4647 父标签 → 默认目录。
中文在裸 `zh` 前增加兼容的 script/region 选择：CN/SG 识别为 Hans，TW/HK/MO 识别为 Hant。
例如 `zh-TW` 可使用 `zh-Hant`，`zh-Hans-CN` 可使用 `zh-CN`；不会把任意缺失地区自动替换成 CN。
缺失翻译的复数和数字格式使用最终供给消息的目录规则。
`resolved_locale(key)` 可以查看该目录标签，`locale()` 则是请求语言。

`direction()` 暴露 START/事件中的方向；手动设语言时按语言/script 推断。
本模块不负责完整双向排版、阿拉伯文 shaping、字体覆盖或自动镜像 UI。
中文大陆字形和黑体选择仍属于字体资源与 Host 文本渲染配置。

## UI 绑定与生命周期

动态文本直接使用现有 `State<std::string>` 与 `ui::Text(state)`，将格式化结果移动到 State：

```cpp
auto label = strings.format(messages::args::items{.count = count});
if (!label) return std::unexpected(label.error());
count_text.set(std::move(*label));
```

无参数消息可以借用静态目录。包含 `<pxa/i18n_ui.hpp>` 后，支持
`State<std::string_view>` 的 Text/Button 和 `State<TextBuffer<N>>` 的 Text。
语言变化或计数变化时重算，State 比较内容并提交必要补丁；没有自动每帧格式化或隐藏的订阅器。
`TextBuffer` 拥有内容，能检测“1 item → 2 items”这类相同长度变化。
不要把反复改写的临时缓冲区借给 `State<string_view>`，否则旧值和新值可能引用同一块内存。
目录、Bundle 必须比 Translator 活得更久；生成器提供的 inline constexpr 数据满足这一要求。

完整示例见 [examples/i18n](examples/i18n/README.zh-CN.md)，验证记录见
[验证报告](examples/i18n/VALIDATION.zh-CN.md)。
