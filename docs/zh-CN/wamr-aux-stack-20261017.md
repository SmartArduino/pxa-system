# WAMR 主线程辅助栈的隐式分割

2026-10-17。已通过原生控制/修复回归、启用 pthread 的 libpxa 回归及 pai-touch 实测，配套固件与微信读书应用已留机。以下结果限于列出的配置和流程。

## 原因

ESP-IDF 配置启用了 WAMR 的 lib-pthread 和线程管理器，却未启用按需子线程栈。
在这一组合下，`thread_manager.c:wasm_cluster_create` 默认把模块辅助栈分给主线程和
四个预留子线程，并把各份大小向下对齐到 16 字节。`RuntimeInitArgs` 清零不会禁用
这项预留，因为 `wasm_cluster_set_max_thread_num(0)` 保持默认值四。

从 pai-touch 精确生产 ELF（`593c5ee3…`，对应 `d8789493…` 镜像）读取的
`cluster_max_thread_num` 初始值为四。当前 PXA 的导入白名单只允许 core ABI 和
已声明的 preview1 服务，并不允许 pthread 或 WASI-thread 导入。

| 链接器声明辅助栈 | 旧策略主线程实际可用 | 按需策略主线程可用 |
|---:|---:|---:|
| 16,384 B | 3,264 B | 16,384 B |
| 32,768 B | 6,544 B | 32,768 B |
| 49,152 B | 9,824 B | 49,152 B |
| 65,536 B | 13,104 B | 65,536 B |

这解释了同一个 16 KiB 微信读书候选在模拟器通过、在 S3 却发生辅助栈溢出的差异。
声明预留和实测水位均不能单独代替运行时实际边界。

## 实现

各平台统一调用 `cmake/PxaWamrRuntime.cmake: pxa_configure_wamr_runtime`。
它保留已有自有 AOT 分节加载策略，并对整个 WAMR target 启用上游已有的
`WASM_ENABLE_HEAP_AUX_STACK_ALLOCATION=1`。主线程使用完整声明栈；只有实际创建
子线程时才分配其栈，结束后释放。最大线程数量未修改，Guest ABI/AOT ABI 未修改，
没有新增线程服务或默认缓冲。该宏会改变 `WASMCluster` 的内部布局，必须一致地
重编译整个 WAMR target，不能只替换一个编译对象。

新平台复用这一入口，不再自行选择一组不一致的加载与辅助栈定义。普通 PXA 应用
仍须通过既有导入和权限校验；本修复没有扩大导入白名单。

## 验证与内存边界

`libpxa/adapters/tests/wamr_aux_stack` 提供独立原生回归及历史控制组，复现命令见
其 README。解释器和 AOT 分别验证 16 KiB 模块的真实 4 KiB 栈工作量，以及三个
子线程的创建、加入和逐一释放。控制组按预期溢出；新策略工作量通过，创建前没有
子线程栈分配，之后三次分配与三次释放匹配。测试中的简化 LIFO 分配器仅用于跟踪
这一序列，不代表应用的通用分配器。

独立 pai-touch 构建先用原策略重编译全部 48 个 WAMR C 文件，确认六个加载段与
精确生产镜像逐字节相同（只排除 appdesc 的构建信息），再整体改为按需策略。
候选镜像 `234edd1978bdefb9c513fc9547328c43004c37ba379f513b38fdf43ec883838e`，
3,445,248 B，比原镜像少 160 B。IRAM、SRAM 静态 data/bss 和 PSRAM 静态 bss
大小不变，Flash text 少 148 B，rodata 不变。共享构建产物未覆盖。

专用回归的新策略/历史控制各四项全部通过；另以 lib-pthread=1 构建 libpxa，
四十项回归全部通过，包含运行时、AOT、导入、超时、资源、网络与绘制等流程。

真机预先固定八次流程：旧 Host/旧 Guest 冷启和重开各一次，新 Host/旧 Guest
各一次，新 Host/同一曾失败的 16 KiB Guest 各两次，全部完成同账号书架和两张
封面；后续真实简介、划线、想法、局部翻页及返回也通过。未重新扫码、未导入
电脑凭据、未尝试此前受限的后续付费章节。启动窗口不截图或开绘制探针，
使用 heap-local 的本次最小空闲值计算峰值，不把启动以来累计最小值当作运行峰值。

同一新 Host 上，新增笔记功能并调整已验证的栈与协程池后，Guest 线性内存
131,072→65,536 B，代码映射保持 1,376,256 B（21 页）；冷/重开的 PSRAM
稳定占用分别少 65,000/65,084 B，窗口峰值少 65,688/65,140 B。
相对原生产组合，冷/重开 SRAM 稳定值不增，峰值分别少 1,128 B/不变。
WAMR 加载峰值 220,332→225,794 B 属于功能增加的模块子计数，不是下降，
且已包含在整机物理堆统计中，不能重复相加。这里只证实配套组合的整机收益，
不能把收益全部归因于运行时开关，也没有宣称 Host 单独运行的每项计数都下降。

最终镜像经设备完整读回核对；仅写应用分区，字体、其他应用、Wi-Fi 和私有
数据保留。本机正常同账号会话轮转被保留。恢复矩阵基线后另行安装新组合，
最终安装烟测独立于固定八次样本，不用于挑选更好的性能数据。新微信读书包
使用 16 KiB 声明栈，必须与这一修复后的 Host 配套；其 AOT SHA256 为
`b2b44db157352ea65644ec6bd9d6b25eb58ebe3a3e88099479c40e1e5b936dfa`。
旧 Guest 无需重新编译。其他设备尚未验证，不因修复隐式分割就任意缩小所有
应用的预留，也不把这组网络书架墙钟时间称作 CPU 或帧率提升。
