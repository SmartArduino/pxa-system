# ESP 固定线性内存的加载预留

固定线性内存（AF07）需要连续地址。在 AOT 代码和元数据之后申请整个上限，
即使总空闲量足够，也可能因为堆分散而失败。ESP 适配层现在先预留该空间，
再装载 AOT，实例化时直接接管原地址。

该优化只应用于普通六节 AOT、单个非共享 wasm32 内存、显式最大页数及已声明
固定内存的组件。预读的声明仅用于放置提示；原有 WAMR 校验仍完整执行。
不支持的布局走原路径，未改变 Guest ABI、导入或权限。

预留区在 Guest 启动前还可容纳临时节数据和重定位数组。只有生命周期确实在
装载返回前结束的三个重定位数组使用借用接口；模块结构、符号字符串和初始化
数据继续由普通分配器持有。所有借用释放后才允许接管，接管时清零整个映射，
避免临时内容对 Guest 可见。预留按运行线程隔离，不借给并发组件。

实例化的映射大小必须与预留精确匹配。Host 堆等配置造成不同时，先释放预留，
再执行普通映射。失败和丢弃模块都会释放尚未接管的空间；接管后的释放及增长
保持原 WAMR 生命周期。借用接口属于适配层内部，不是供应用调用的 SDK 接口。

WAMR 修改位于 `tools/wamr/patches/`，构建生成自有覆盖，不直接修改上游目录。
补丁清单中的全部文件都参与 CMake 配置依赖。

## 验证范围

`platforms/esp-idf/wamr/tests/test_host.sh` 使用 ASan/UBSan 验证地址接管、清零、
借用未释放时禁止接管、大小不匹配、分配失败、失败回收和线程隔离。

libpxa 的 `pxa_wamr_aot_reader_test`、`pxa_wamr_reserved_reader_test` 和
`pxa_wamr_engine_test` 在普通及 ASan/UBSan 构建下通过。预留测试在执行模块前
污染已归还的临时内存，确认初始化数据和符号已经正确独立持有；相同堆限额下，
普通读取失败而临时借用读取成功。另覆盖短读、截断及分配失败回收。

2026-10-19 GameKit / ESP32-S31 上，OpenLara 0.2.7 的 8MiB 固定预留被接管，
临时借用峰值 280,584 字节，应用实际启动并输出音频就绪。Quake II 0.1.6 的
10.25MiB 预留成功，但模块装载仍因额外内存不足失败；不能将此优化称为该游戏
已能运行，也不能把累计 PSRAM 最低空闲值当作每次启动的内存峰值。

后续 FW28 的 Quake II 0.1.7 使用 10.1875MiB 上限完成冷启动装载：预留被接管，
临时借用 1,420,984 字节，收到 `Started verified Package`；启动就绪时 PSRAM
空闲353,300字节。引擎池仍为7.5MiB。原有应用版本保留，测试后 OpenLara 的
前台状态及音频就绪通过。此时尚未完成游戏资源上传，结果只证明模块装载，
不代表已经进入关卡或达到15fps。
